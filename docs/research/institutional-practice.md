# 調査: 機関投資家の実務(ガバナンス・組織・リスク管理・ファンド会計)(2026-08-02 時点)

設計根拠資料。v2 設計(部門構成・リスクエンジン・会計係)の接地に使用。

## A. ガバナンス(GPIF・IPS)

### GPIF の構造
- **基本ポートフォリオ**: 4資産(国内債・外債・国内株・外株)各25%。資産ごとの乖離許容幅(±5〜6%)+債券全体・株式全体に±9%の「2階建て」管理。幅内は機動的運用を許容、超過でリバランス
- **ガバナンス**: 経営委員会(方針決定・監督)と執行(理事長・投資委員会=重要判断の事前審議)の分離。「投資原則」を憲法的文書として明文化
- **個人システムへの移植**: 政策ウェイト+2階建て許容幅は設定ファイルに写せる。方針変更=人間承認、幅内運用=自動、のゲート設計が GPIF 型。投資原則(IPS)を最上位文書とし全エージェントに注入
- 出典: gpif.go.jp(基本ポートフォリオ・経営委員会・投資原則)

### IPS(投資方針書)標準構成(CFA Institute)
1. 範囲と目的 2. ガバナンス(各当事者の責務・改定手続) 3. リターン・リスク目標 4. 制約(流動性・期間・規制) 5. リスク管理・モニタリング・報告 6. 付録(政策ミックス・ベンチマーク・リバランスルール)
- 個人版: Markdown 1枚を「単一の真実」とし、コンプライアンス/リスク両エンジンが機械可読形式で参照

## B. 運用会社の組織(フロント/ミドル/バック)

| 部門 | 責務 | 成果物 | サイクル |
|---|---|---|---|
| PM(フロント) | 戦略・ポートフォリオ構築・売買判断 | モデルポートフォリオ、注文指示、判断メモ | 日次+月次レビュー |
| トレーディングデスク(フロント) | 最良執行・執行コスト管理 | 約定記録、執行報告(TCA) | 日次 |
| リスク管理(ミドル) | 市場・信用・流動性リスク監視、リミット管理 | 日次リスクレポート、超過アラート | 日次+月次ストレステスト |
| コンプライアンス(ミドル) | プレ/ポストトレードチェック、制限リスト | 違反アラート、報告書 | 発注都度+日次 |
| トレードサポート/IBOR(ミドル) | 約定記帳・照合・ポジション正本維持 | 確定取引記録 | 日次(T+1決済) |
| ファンド会計(バック) | NAV 算出・評価・費用計上 | 日次 NAV、月次試算表 | 日次締め |
| パフォーマンス測定(バック) | TWR・要因分解・ベンチマーク比較 | 月次レポート、アトリビューション | 日次計算+月次 |
| 決済・照合(バック) | リコンシリエーション | 照合結果、ブレイクレポート | 日次 |

核心: **フロントとミドルの独立性**、**バックが独立に帳簿を持ち照合する**こと。

### プレトレード・コンプライアンス標準項目
集中度上限(銘柄/セクター/資産クラス)、制限銘柄、レバレッジ/グロス・ネット上限、流動性(出来高比)、買付余力、マンデート適合。ソフト(警告)/ハード(ブロック)の2段階+全結果の監査ログ。個人では「1日あたり売買代金上限」等の**エージェント暴走ガード**が実務以上に重要。
実装: 発注直前の純関数 `check(order, portfolio, rules) -> pass | warn | block`

### パフォーマンス測定
- **TWR**: 日次 NAV があれば日次リターンの幾何連結で GIPS 相当精度
- **Brinson-Fachler**: 超過リターンをアロケーション/セレクション効果に分解。資産クラスレベル・月次が現実的。エージェント単位の意思決定評価に転用可能
- GIPS 準拠は不要だが「全口座・同一手法・月次」の規律だけ移植

## C. ポートフォリオリスク管理

### 指標の最小推奨セット(個人規模)
- **ヒストリカル VaR/ES(95%・1日・250〜500日)** を本命に(バーゼル FRTB も 97.5% ES に移行済み — ES はテール暴走検知に向く)
- パラメトリック VaR を併算し乖離を監視(健全性チェック)
- 年率ボラ、対ベンチマークベータ、ex-post トラッキングエラー

### 共分散推定
- 日次 VaR 用: **EWMA(λ=0.94, RiskMetrics)** / 配分最適化用: **Ledoit-Wolf シュリンケージ**(sklearn で1行)。ルックバック250〜750日

### ファクターモデル
- フル Barra は非現実的。**Fama-French 型公開ファクター回帰**(Kenneth French データ、無料)で「意図しないベット検知」に簡略化

### ストレステスト(月次)
- ヒストリカル3本(リーマン、コロナ、金利ショック)+仮想3本(株−30%、金利+2%、円高15%)。シナリオ=ショックベクトルとポジションの内積。「想定損失 NAV の X% 超で人間へエスカレーション」

### デリバティブ・信用のエクスポージャー集計
- ポジションはデルタ調整後等価額で計上。日次4集計: ①グロス(|L|+|S|) ②ネット(L−S) ③レバレッジ(グロス/NAV) ④通貨別ネット
- マージン3段構え: ブローカー API から維持率取得 → 自前計算と照合 → 閾値(規制水準+バッファ)割れで新規建てブロック+通知

## D. ファンド会計

### 日次 NAV プロセス
①ポジション・現金・コーポレートアクション取込 → ②ポジション照合 → ③価格付与(ステイル検査) → ④評価損益+費用アクルーアル → ⑤レビュー・承認 → NAV 公表

### 記帳原則
- **約定日ベース**で認識。複式簿記で取引・評価損益(実現/未実現を分離)・費用(発生主義)・分配を記帳、試算表を維持
- 個人では**自前帳簿=シャドー会計**、ブローカーが公式帳簿。日次照合で不一致は「ブレイク」としてキュー管理+通知。「一致→NAV確定、不一致→暫定」のステータス管理

### 勘定科目の最小セット(15〜20科目)
- 資産: 現金/有価証券(資産クラス別)/未収配当・利息/未収入金(売却未決済)/差入証拠金
- 負債: 未払金(買付未決済)/借入金(信用)/未払費用/空売り有価証券
- 資本: 出資金/累積損益
- 収益: 配当/利息/実現損益/未実現評価損益(分離必須)
- 費用: 売買手数料/支払利息/データ・システム費/(LLM API 費もここ)

## 総括 — 設計への3示唆
1. **統制の3層構造**: ①方針(IPS=人間承認)②発注前ゲート(決定論ルール)③事後検証(日次リスク・照合・月次アトリビューション)。AI の自律性は②③で挟む
2. **二重帳簿+日次照合**が最も費用対効果の高い「機関っぽさ」— AI の記帳ミス・幻覚・API 障害の検知網
3. リスクエンジン最小構成 = ヒストリカル VaR/ES + EWMA/Ledoit-Wolf 併算 + 乖離幅監視 + 月次ストレス6本 + デルタ調整グロス/ネット/通貨集計
