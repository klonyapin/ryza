# Ryza 投資方針書(IPS)v1.3

> **二層構造への改組(2026-08-03 ユーザー起票・方針承認)**: IPS は「資本の所有者(ユーザー)とシステムの契約」としてファンドレベルの一枚だけを置き、ファンドマネージャー(FM)ごとの運用規定は **FM マンデート**([81-fm-mandates.md](81-fm-mandates.md))として分離した。実務の対応物: GPIF の中期計画(=IPS)と外部委託先ごとの運用ガイドライン(=マンデート)。旧 v1.0 の「IPS プロファイル」は次の2概念に分解された:
> - FM ごとの運用の色 → **マンデート**(81 へ移動)
> - E8 スイープ用のファンド全体パラメータのバリエーション → **実験プロファイル**(本書 §6)

- ステータス: **発効(2026-08-03 ユーザー承認・Issue #4)**。§7 論点は 2026-08-03 解消済み。独立レビュー(docs/reviews/ips-v1.2-independent-review.md、条件付き承認)の必須条件1〜5を v1.3 で反映済み
- 骨格: CFA Institute 機関投資家向け IPS 標準構成(政策ミックスは v1.2 でリスク予算方式に置換)
- 確定後: 機械可読版 `config/ips.yaml` を生成し、コンプライアンス・リスク両エンジンはそれのみを参照する
- 変更手続: **ユーザーのみ起票可**(保護領域)。全変更は版管理+承認記録
- 優先順位: 本書はマンデートに常に優先する。ゲートは IPS → マンデートの順に判定し、マンデートが IPS を緩める方向の記述を持つことはスキーマで禁止する

## 1. 範囲と目的

- 投資家: ユーザー個人(自己資金・自己運用)
- 対象: Ryza が管理する全帳簿(当面 DEMO_FUND のみ。基準通貨 JPY、出資金 ¥10,000,000 = 初期 ¥1,000,000+2026-08-03 増額 ¥9,000,000)。**全 FM ポッドの合算に適用する**
- 実験資金と実弾の分離(2026-08-03 ユーザー決定): デモは運用の器(マルチポッド・政策ミックス・単元制約)が機能する規模で回す。実弾移行時は少額から別途開始し、**戦略の採用判定は E8 スイープ(¥10万〜100万)の実弾想定規模でのみ行う** — 大 NAV で薄まった E4 コスト比を採用判定に使わない
- 目的: 自己資金の長期成長と、自己進化型運用システムの検証・学習の両立。デモ期間中も本 IPS を実弾と同じ規律で適用し、規律遵守の実績自体を実弾移行の判断材料とする

## 2. ガバナンス

- 投資委員会(ユーザー): 本書・リスク予算・ガードレール・マンデート交付・戦略昇格・システム変更の承認。緊急停止権限
- システム(Ryza): ガードレール(§4.2)内、かつ各 FM のマンデート範囲内での運用裁量

### 2.1 IPS 改訂フロー

原則: **発効の決定権は常にユーザー。ただし見直しの契機・批判はシステム側からも出す。**

1. **月次定期レビュー**(営業期間=1ヶ月の圧縮サイクルに整合。00-system-design.md §8): CIO ペルソナ(05-governance.md — セッションに依存しない役職資産)が「IPS 批判レポート」を起草し、独立役員ペルソナの意見書を添えて、投資委員会で代表と対話して改訂を検討する。レポートの必須内容:
   - 遵守実績(ゲート却下・リミット超過の統計)
   - 制約がバインドした箇所(「この制約がなければ何をしていたか」の機会費用分析)
   - IPS 自体への批判(矛盾・実務との無理・形骸化した条項の指摘)
2. **臨時見直し提案**: 次のトリガーで Fable・リスク管理部・監査部門は随時「見直し提案」を起こせる(発効はユーザー確定のみ):
   - DD ソフトリミット到達 / 監査 critical 指摘 / ストレステストのエスカレーション / 市場レジームの構造変化
3. **確定手続**: 対話 → 改訂案(diff 明示)→ ユーザー確定 → 版番号+効力発生日を記録 → `config/ips.yaml` 再生成 → エンジンが新版参照。旧版は履歴保持
4. 頻繁な変更の抑制: 定期レビュー以外の改訂は原則トリガー事由がある場合のみ。改訂履歴自体もレビューの評価対象(「ルールを曲げた回数」を可視化)

## 3. ファンド全体のリターン・リスク上限

いずれも**全ポッド合算**の値。FM 別のリスク予算はマンデートで配分するが、配分の合計や相関の変化によらず本節の上限が最終防衛線となる(ポッド別上限の総和はファンド保証にならないため、中央リスク管理部が合算値を常時監視する)。

### 3.1 目標リターンの導出規約(2026-08-03 ユーザー起票: 金融工学ベース。v1.3 で独立レビュー指摘を反映し再較正)

目標リターンは独立に選べる値ではなく、**E[R] ≈ SR × σ** の関係から導出する(SR = シャープレシオ仮説、σ = 年率ボラティリティ予算)。σ は DD 上限から逆算する。

**DD の測定定義(独立レビュー条件1)**: DD は**帳簿単位・設定来ピークからの下落(連続測定・リセットなし)**で測る。したがって較正も運用想定ホライズン(**3年**・連続測定)で行う — v1.2 の「年内」較正はこの定義と不整合だったため破棄。

再較正(2026-08-03、8千パス×756日、GBM と i.i.d. t(4) の両分布。docs/research/mc-dd-vol-calibration.md に追記):

| SR 仮説 | σ予算 | E[R](算術) | 3年内に DD>25%(GBM / t4) |
|---|---|---|---|
| 1.0 | 10% | ≈10% | 1.0% / 1.4% |
| 1.0 | **12%** | ≈13% | **3.3% / 3.6%** |
| 1.0 | 15% | ≈16% | 11.1% / 10.4% |
| 1.0 | 20% | ≈22% | 32.9% / 30.4% |

- **運用値: σ予算 = 12%(暫定)**。ブリーチ確率 ≤10%(3年・連続測定)に対し 3.3〜3.6% と余裕を残すのは、較正が捉えていない既知の下方バイアス(ボラクラスタ・負の歪度・ストレス時のポッド間相関上昇)へのヘアカットである。実績分布での再較正(研究本部)まで σ予算の上限は 12% とする
- **SR 仮説**: 初期値は**縮小推定**(事前分布 SR 0.5 への shrinkage)から開始し、**四半期更新**・信頼区間併記(独立レビュー指摘: 実績ゼロの新システムに SR 1.0 を「保守的」と呼ぶのは楽観側。月次更新は推定ノイズの制度化)。したがって目標リターンは断定値でなく**条件付きレンジ: SR 0.5〜1.0 の実現で年率 6〜13%(算術。幾何=体験リターンは σ²/2≈1pp 低い)**
- 年率 100% 級は本則(DD25%)とは両立しない(§6 moonshot に隔離)。E5 との整合: 四半期未満の SR 差で目標・配分を動かさない

### 3.2 リスク上限(ハードリミット)

本節の値は**基準プロファイル(aggressive)の既定値**であり、実験プロファイルは §6 の手続で**帳簿単位**に別値を持つ(実弾帳簿は本則のみ・プロファイル化不可)。適用・監視は帳簿単位で行い、moonshot 等の高リスク帳簿の損失が本則帳簿のブレーカーを誤発動させることはない(独立レビュー懸念5)。

| 項目 | 値 | 備考 |
|---|---|---|
| **最大ドローダウン許容** | **25%**(確定) | サーキットブレーカー発動点。測定は §3.1 の定義(設定来ピーク・連続・帳簿単位) |
| **実現ボラティリティ上限** | σ予算(12%)+3pp | EWMA(20日)の年率換算が超過で新規建てブロック(σ予算の執行機構 — 独立レビュー条件2)。ポッド間相関を考慮した合算 σ は中央リスク管理部が常時監視 |
| DD 15% 到達時 | 警告+新規建て枠を半減(ソフトリミット) | 段階的ディフェンス |
| DD 25% 到達時 | 全新規発注停止(ハードリミット)。復帰は委員会の明示操作のみ | |
| 日次 ES(95%)上限 | NAV の 3% | 超過で新規建てブロック+通知 |
| **レバレッジ上限(グロス/NAV)** | **2.0x**(確定) | 維持率はブローカー要求+バッファ 20% を下回ったら新規建てブロック |
| **1銘柄集中度上限** | **NAV の 20%**(確定) | 発行体単位・**全ポッド合算** |
| 1日の売買代金上限(暴走ガード) | NAV の 30% | 全ポッド合算 |
| ベンチマーク | ①参照ミックス複製(§4.3 の評価専用ミックス)②等配分 buy-and-hold | ②は評価プロトコル E3 と整合 |

**dd_hard 復帰手順の前提確認(2026-08-04 CIO 起票・独立役員審査 docs/reviews/risk-observability-independent-review.md の留保条件)**: 復帰の可否は、フラグが立った時点の測定前提が健全だったかを確かめたうえで審議する。具体的には、復帰審議に入る前に、dd_hard を設定したイベント(`risk.limits_state_events` の `event=engine_update`)の `metrics.close_ok` / `metrics.close_self_checked` を確認する。リスク日次は当日の会計締めが失敗しても測定を止めず、前日までの系列に基づく旨を宣言して続行する設計であり、締めが完了していない日は `close_ok=false` が記録される(`src/ryza/risk/daily.py`。締めの成否を知らされない実行では当日 NAV スナップショットの有無で自己検証し、`close_self_checked=true` が付く)。`close_ok=false` の場合、DD は未再締めの系列(遅延仕訳が入ったままの NAV)で測られた可能性があるため、締めを完了させたうえでの再測定を先に行い、その結果をもって復帰可否を判断する。この確認を欠くと、締め障害に由来する誤 dd_hard が委員会専決のラッチとして残り、解除のたびに委員会の議事を消費する。復帰操作そのものは従来どおり委員会の明示操作のみであり(本節の表・`risk.state.release_dd_hard`)、本項は復帰の要件を緩めない。

## 4. エクスポージャー配分(政策ミックス廃止 — 2026-08-03 ユーザー起票)

v1.1 までの固定政策ミックス(GPIF 型目標ウェイト)は年金型の構造であり、ポッド型(マルチマネージャー)と整合しないため廃止。資産配分は FM の裁量に委ね、ファンドレベルは**リスク予算とガードレール**だけを持つ(ポッド型ヘッジファンドの実務: Millennium/Citadel 型は資産クラスの目標ウェイトを持たず、ポッドへのリスク予算配分で全体を制御する):

1. **リスク予算配分(§4.1)**: ファンドの σ予算(§3.1)をマンデートで各ポッドへ配分(ポッド別 σ配分・レバ上限は 81 §3 の表とおり)。資産クラスの目標ウェイトは定めない
2. **エクスポージャー・ガードレール(§4.2)**(上限であって目標ではない。ゲート対象。資産クラスの分類は §8.1 のタクソノミーによる):

| ガードレール | 値 | 趣旨 |
|---|---|---|
| 単一資産クラスのグロス | NAV の 70% 以下 | 全ポッドが同一ベータに集中する事故の防止 |
| 暗号資産 | NAV の 5% 以内 | 休眠条項 — 初代4名のユニバースに暗号資産はなく、有効化はマンデート改訂(ユーザー承認)による |
| 現金下限 | NAV の 5% | 流動性・追証バッファ |
| 発行体集中度 | 20%(§3.2 再掲) | |

3. **ベンチマーク(§4.3)**: 旧政策ミックス(国内株30/外国株30/債券15/戦術10/現金15)は**評価用の参照ミックスとしてのみ**残す(E3 の等配分 B&H と併用)。運用をこれに寄せる義務はない
4. **リバランス条項は廃止**(目標ウェイトがないため)。ガードレール超過時のみ、ゲートが新規建てを拒否し超過解消の注文案を生成する
5. 配分変更の摩擦(売買コスト)は事前の頻度規制でなく、TCA と E4 全コスト込み評価で捕捉する — コストで負ける配分変更は成績で罰される構造を優先する

## 5. 禁止事項・Kill Switch

| 項目 | 値 |
|---|---|
| 取引頻度 | **制限しない**(2026-08-03 ユーザー決定: 高回転は機械の強み。旧「最低保有期間1営業日」は廃止)。過剰取引の抑制は事前規制でなく TCA+E4 全コスト込み評価とマンデートの回転参照値で行う。イントラデイ回転は執行インフラの対応範囲に依存(現状はデータが EOD 中心・日次サイクルのため、イントラデイ戦略はデータ基盤拡張後に解禁。コロケーション級の真の HFT は個人環境では構造的に不利であり対象外) |
| 禁止対象 | レバレッジ型・インバース型 ETF / 監理・整理銘柄 / 制限銘柄リスト(config で管理)。レバ型 ETF 禁止の理由: ①日次リバランス構造によるボラティリティ・ドラッグで長期保有では原指数の N 倍にならず減価する ②帳簿上1単位でも実効エクスポージャーが N 倍のため、レバレッジ上限 2.0x やデルタ調整集計の計算を狂わせる「見えないレバレッジ」になる。同じ積極性は信用・先物の「測れるレバレッジ」(2.0x 枠)で取る |
| ショート | 許可(レバレッジ・集中度の制約内。個別銘柄ショートは1銘柄 NAV の 10% まで) |
| Kill Switch(多段・2026-08-03 改訂) | ユーザーはいつでも発動できる(Discord・保護領域)。**凍結が常に最善ではない**(凍結中も市場リスク・追証・デリバティブ満期は残る)ため3モード: ①**`/kill`(凍結)** = 全新規発注停止・ポジション維持。「システムが信用できない」時の既定(バグの疑いがある系に清算までさせない)。凍結中の例外的取引は 1件ずつユーザー承認 ②**`/winddown`(計画的現金化)** = 決定論アルゴ(TWAP 等)で市場インパクトを抑えて段階的に全ポジションを現金化 ③**`/flatten`(緊急清算)** = 成行で即時全清算。コスト・スリッページを受け入れる緊急用。2段階確認必須。②③は LLM を経由しない決定論コードのみで実行。凍結中もブローカー強制決済・満期等の受動イベントは発生しうるため、検知次第 #運営 へ即時報告。復帰はユーザーの明示操作のみ |

- 禁止事項はマンデートで**狭める**ことはできるが、**緩める**ことはできない

## 6. 実験プロファイル(開発フェーズの並走運用)

実弾移行までは、本書 §3〜4 のパラメータ組を「実験プロファイル」として複数並走させてよい — 例: aggressive(本書の値: DD25%・レバ2.0x)/ moderate(DD15%・1.5x)/ conservative(DD10%・1.0x)/ **moonshot(DD60%・σ予算50%・レバ2.0x — 2026-08-03 ユーザー要望の年率100%級を狙う枠。旧較正(年内測定)では SR 1.5 実現時 E[R]≈110%・年内 DD>60% 確率は数%だが、§3.1 の新定義(3年連続測定)では上振れするため moonshot 帳簿の較正は起票時に §3.1 と同一手法で再計算する。また、SR 仮説が外れると期待値は急落する(SR 0.5 なら E[R]≈27%・DD>25% 確率 91%)。実現可能性の検証自体が実験目的)**。仮想帳簿・バックテストごとにプロファイルを割り当て、E8 スイープの次元(資本×開始時点×プロファイル)として検証し、実弾移行時にデータに基づき単一の値を確定する。

制約(2026-08-02 投資委員会):
1. プロファイルは実験中凍結(途中変更はその実験を無効化)
2. ガバナンス(§2)・禁止事項(§5)・予算・保護領域・監査はプロファイル化せず唯一のまま
3. 並走数に固定上限は設けない — 経営管理部の月次予算と E9 多重検定補正(母数増を自動ペナルティ化)が原理的な制約として効く

注: 実験プロファイルは**ファンド全体パラメータのバリエーション**であり、FM ごとの運用の色(マンデート)とは別概念。1つの実験帳簿の中に複数 FM ポッドが存在し、それぞれのマンデートで運用される。

**E8 小規模帳簿の縮約規則(独立レビュー C-14)**: ¥10万〜100万の E8 帳簿ではマルチポッド構造(各¥200万)は構成できないため、**単一ポッド縮約**(検証対象戦略のマンデートのみ適用・中央リザーブなし)で走らせる。E8 が検証するのは戦略の実弾規模での成立性であり、マルチポッド構造自体の検証はメインデモ帳簿(¥1,000万)で行う — 両者の結果は別の問いに答えるものとして分離して報告する。

## 7. 解決済み論点(2026-08-03 ユーザー決定)

1. **単元例外(集中度20% × 日本株単元制約)**: 日本個別株は**1単元までは集中度20%の超過を許容**する(2単元目以降は通常判定)。全帳簿共通(E8 小規模帳簿を含む)。少額投資家の現実の制約をそのまま写した評価にするための実務例外であり、コンプライアンスゲートに例外条件として実装する。**例外の上限(v1.3・独立レビュー条件3)**: 例外が適用されるのは1単元の取得価額が **NAV の 35% 以下**の銘柄に限る(値がさ株で集中度上限が実質無効化するのを防ぐ)。例外適用ポジションの**信用買いは不可**。上限超の値がさ株は「その規模では買えない」— これも E8 の情報として扱う(§7-2 と同じ思想)
2. **コスト按分は実額のまま(E4)**: 仮想料率への置換は行わない。運営実費(LLM 費等)は実額で各帳簿に按分し、小規模帳簿がコスト支配で不成立になる結果も**それ自体を情報として扱う**(「その規模ではコスト構造上成立しない」という結論を隠さない)。診断用にコスト控除前の指標も併記してよいが、**採用判定には使わない**(E9 の生 Sharpe 禁止と同趣旨)

## 8. 分類・商品・通貨・時間軸(v1.3 追加 — 独立レビュー §8 指摘の即応分)

### 8.1 資産クラス・タクソノミー(ガードレール判定用)

`equity_jp` / `equity_us` / `equity_other` / `bond` / `fx` / `crypto` / `commodity_futures` / `rates` / `cash`。指数先物・ETF は**原資産のクラス**に分類する(株価指数先物 = equity、金利先物 = rates)。§4.2 の「単一資産クラス 70%」は equity_jp と equity_us を**別クラス**として判定する。機械可読の分類マスタは `config/ips.yaml` に含める。

### 8.2 デリバティブ・商品方針

**IPS が明示的に許可しない商品はデフォルト不可**(マンデートが商品方針を新設することはできない — 「狭める方向のみ」原則の系)。許可リスト: 上場現物株式・ETF・上場先物(指数・金利・コモディティ)・取引所 FX。**OTC デリバティブ・オプションは現時点で不可**(オプションはギリシャ管理の実装後に改訂で解禁を検討)。

### 8.3 通貨方針

基準通貨 JPY。**為替ヘッジは行わない**(ヘッジコストと運用規模が見合わないため)。外貨建てポジションの為替リスクは σ予算に内包し、中央リスク管理部が**円換算**で計測・監視する。Stan の FX ポジションは戦略ポジションであり、ヘッジとは区別して記帳する。

### 8.4 時間軸・流動性・税制

- **時間軸**: 検証運用(デモ)3年以内を想定し、DD 較正ホライズン(§3.1)もこれに整合。実弾移行判断はその成績蓄積後
- **流動性**: デモ中は引出し要件なし。実弾 IPS には「資金拘束期間・生活資金との分離」条項を必須とする
- **税制**: デモには適用なし。**実弾移行時、税制条項(譲渡益・配当課税、口座区分、先物/FX の申告分離と損益通算不可、E4 への税コスト算入)なしでの移行を不可とする**(独立レビュー条件7)
