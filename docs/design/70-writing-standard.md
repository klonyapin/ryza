# Ryza 執筆規格(Writing Standard)v1.0

- 制定日: 2026-08-02(ユーザー指示による)
- 適用範囲: **価値のあるすべての文章** — 研究論文・テーマレポート・月次報告・監査報告・朝刊(短縮形)など
- 位置づけ: 保護領域文書(変更はユーザー承認必須)。執筆エージェントのプロンプトとリンターの仕様の源泉

## 0. 基本構造

すべての文書はセクションを次の3部で構成する:

```
セクション
 ├ イントロ
 ├ 本文
 └ 結論
```

---

## 1. まずは、形式を学ぶ(型習得フェーズ)

新しいジャンル・媒体で書く前に必ず実施する。結果は研究リポジトリに「型データ」として保存し再利用する。

### 1.1 モデル論文をピックアップする
- その媒体以外から選ばない
- なるべく新しいものを選ぶ(ジャーナル論文であれば10年以内)
- 自分の関心と近すぎないトピックの論文を含める
- その媒体に複数の論文を載せている著者を見つける
- 生産的な若手研究者を見つける

### 1.2 計測
- 全てのパラグラフに番号を振り、全部で何段落あるか数える
- 各パラグラフの字数をおおまかにカウントする
- パラグラフの長さの平均(中央値)をとる
- イントロと結論のセクションは除く

### 1.3 設定
- 計測した値から、自文書の**パラグラフの総数**と**パラグラフの長さ**を設定する

### 1.4 パラグラフ解析 [Uneven U]
センテンスの抽象度を5段階に分ける:

| レベル | 定義 |
|---|---|
| 1 | 純粋なファクト |
| 2 | 観察。明らかな、あるいは解釈的な要約 |
| 3 | 概念的要素のまとめ。2つ以上の証拠をまとめて書くか、幅広い例を提示する |
| 4 | あまり一般的ではない文章。問題に向けた方向付け。アイデアをまとめて引き寄せる |
| 5 | アブストラクト。アーギュメント |

**4→3→2→1→3→5 のように U字になることが理想。**

## 2. 先行研究の引用

### 2.1 データの取得
- 引用文献を、**研究書**と**ジャーナル論文**で分ける(ハイライトで色付けする)
  - 新聞・図書館アーカイブ・小説や映画などのリソースからの引用が多い場合はそれもジャンル分けする
  - 「何本の論文と何冊の研究書を引用すればよいか」を数値データとして把握する
  - **モデル論文2本が共に引用している資料は必須文献**と考えてよい
- 引用箇所をハイライトする
- 参照されている文献を入手し、書籍・論文の**どの箇所**から引用しているのかを調べる

### 2.2 アーギュメントを見つける
- アーギュメントだと確信できるセンテンスにハイライトを付ける(アブスト・イントロ・コンクルージョンにある)
- アーギュメントを**自分の言葉でパラフレーズ**し、記録する(アーギュメント・パラフレーズ集として蓄積)

---

## 3. 先行研究(研究書)を読む

- 研究書を手に入れる
- 裏表紙の推薦文と著者自身のアブストから、**書籍全体のアーギュメント**を抽出する
- **各章のアーギュメント**を赤でハイライトする(章の最初と最後に書いてあるはず)
- 情報を5層に分ける:
  1. アーギュメント — ぜひ引用したい
  2. 個人的に興味があり、引用する可能性もある
  3. ファクト — 本からではなく、一次資料にあたって引用する
  4. 軽く重要だと思った箇所 — 引用してもよい
  5. 上記以外 — 引用しない

---

## 4. イントロダクションの書き方

必須要素: **アーギュメント/アカデミックな価値/シノプシス**

順番:
1. **冒頭部分**
2. **先行研究パラグラフ**
3. **アーギュメント・パラグラフ**
   - アーギュメントの真意を伝えるために必要十分な周辺情報や文脈を盛り込む
   - 抽象度や視点を変えながら、アーギュメントを何度かパラフレーズする
4. **シノプシス**(1パラグラフを割く)

---

## 5. 結論の書き方

- 自分の議論の**応用可能性**に言及する
- 型(いずれかを選ぶ):
  1. 研究プロジェクトを売り込む
  2. 時事問題に接続する
  3. 新しいエピソードに導入する
  4. 自分を登場させる

---

## 6. Ryza での機械化(実装仕様)

執筆パイプライン:
1. **型データ参照**: 対象ジャンルの型データ(モデル論文の計測値: パラグラフ総数・長さ中央値・引用数構成)を読み込む。無ければ §1 の型習得フェーズを先に実行
2. **執筆**: エージェントは各センテンスに抽象度タグ(1〜5)、各引用に文献種別タグを付けて出力
3. **リンター検査(決定論)**:
   - パラグラフ総数・長さが型データの設定範囲内か
   - 各パラグラフの抽象度系列が U字(高→低→高)か
   - レベル1(ファクト)の文に出典参照があるか
   - 引用数(論文/研究書/その他)が型データの範囲か
   - イントロが「冒頭→先行研究→アーギュメント(複数回パラフレーズ)→シノプシス」の順か
   - 結論に応用可能性への言及と型(1〜4)の採用があるか
4. 不合格は理由付きで再生成(最大 n 回、超過時は人間へ)

研究リポジトリの蓄積物: 型データ / 必須文献リスト(モデル論文2本共通引用)/ アーギュメント・パラフレーズ集 / 読書ノート(5層分類)

## 7. Fable の研究ノルマ

- **1日1本**の研究論文を戦略研究班の Fable に課す(ユーザー指示)
- パイプライン(仮説キュー・データ準備・E1〜E7 バックテストの自動実行)が素材を常時供給し、Fable は研究設計・分析・執筆に集中する
- 本規格 §1〜5 に完全準拠。E1〜E7 の検証記録を必ず含む
- トークン消費は経営管理部の予算科目「研究(Fable)」として月次予算で管理
