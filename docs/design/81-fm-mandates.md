## 1. マンデートとは

投資委員会が **IPS の範囲内で** FM ポッドごとに交付する運用規定。FM の「哲学の器」(charter)が*どう考えるか*を定めるのに対し、マンデートは*何をどこまでやってよいか*を定める。両者は分離する — charter は FM 自身の人格資産、マンデートは委員会がコントロールする契約。

構成要素:

| 要素 | 内容 | 例(Ben) |
|---|---|---|
| ユニバース | 売買してよい資産クラス・市場 | 日本株・米国株の現物のみ |
| スタイル規定 | 想定回転・保有期間の目安(評価の参照値。ゲート対象ではない) | 低回転(月数回) |
| 仮想資本配分 | ポッドに割り当てる資本(月次で成績再配分) | ¥2,000,000 |
| ポッド別リスク予算 | ポッド内 DD・ポッド内集中度など、IPS より狭い上限 | ポッド DD 20% で新規建て停止 |
| 禁じ手 | IPS 禁止事項に**追加**でそのポッドに課す禁止(緩和は不可) | デリバティブ・ショート禁止 |
| ベンチマーク | ポッド成績の比較対象(E3/E9 評価に使用) | ユニバース等配分 buy-and-hold |

## 2. 交付・改訂フロー

1. **起案**: CIO ペルソナ(新規 FM 孵化時・月次再配分時)。FM 本人は自分のマンデート変更を**提案**できるが起案・承認はできない
2. **審査**: 独立役員ペルソナが意見書(懸念最低1件)を添付
3. **承認**: 投資委員会(ユーザー)。交付・改訂はすべて版管理+承認記録
4. **機械可読化**: `config/mandates/<fm>.yaml` を生成。コンプライアンスゲートは **IPS → マンデートの順**に判定する(マンデートは IPS を狭める方向のみ有効。緩める記述はスキーマ検証で拒否)
5. FM の売買は全て中央のコンプライアンスゲート経由(40-fund-managers.md 制約3と同一。哲学は銘柄選択と保有期間に現れ、リスク上限は誰も破れない)

## 3. 初代4名のマンデート初版(承認済み 2026-08-03)

DEMO_FUND ¥10,000,000(2026-08-03 増額)。各 ¥2,000,000+中央リザーブ ¥2,000,000(リバランス・新 FM 孵化用)。月次で成績再配分(E9 補正済み指標のみ)。

| 項目 | **Ben** | **Jim** | **Stan** | **Peter** |
|---|---|---|---|---|
| ユニバース | 日本株・米国株 現物 | 流動性の高い株・ETF・株価指数先物 | 指数(先物/ETF)・FX・金利系 | 日本株中堅・米国株 現物 |
| スタイル(参照値) | 低回転(月数回)・長期保有 | 高回転(日次)・統計的エッジ | 中回転(週数回)・非対称ベット | 中回転・GARP |
| 仮想資本 | ¥2,000,000 | ¥2,000,000 | ¥2,000,000 | ¥2,000,000 |
| ポッド DD 上限 | 20%(新規建て停止) | 15%(同左) | 22%(同左) | 20%(同左) |
| ポッド σ配分(対仮想資本・年率) | 12% | 15% | 25% | 15% |
| ポッド・グロスレバ上限(対仮想資本) | 1.0x(現物のみ) | 1.5x | 3.0x | 1.0x(現物のみ) |
| ポッド内1銘柄集中度 | 仮想資本の 40% | 同 20% | 同 50%(指数・FX のみのため) | 同 30% |
| 追加の禁じ手 | デリバティブ・ショート・信用 | 個別銘柄の裁量判断(シグナル外の売買) | 個別株 | デリバティブ・ショート |
| ショート | 不可 | 先物ヘッジのみ可 | 可(FX・指数) | 不可 |
| ベンチマーク | ユニバース等配分 B&H | 同左 | 同左 | 同左 |

- σ配分の整合(v1.3): ポッド σ の資本加重和は相関1の最悪ケースで 0.2×(12+15+25+15)=13.4% とファンド σ予算 12% をわずかに超えるが、哲学の直交性(40-fund-managers.md)による低相関を前提とした配分であり(平均相関 ≤0.3 なら合算 ≈7%)、最終防衛線はファンドレベルの実現ボラ上限(IPS §3.2 の EWMA ゲート)が担う。グロスレバの資本加重和は 0.2×(1.0+1.5+3.0+1.0)=1.3x < ファンド上限 2.0x
- Jim の禁じ手「シグナル外の売買」の執行(v1.3・独立レビュー C-13): 全注文に signal_id の紐付けを必須とするデータ契約で機械判定する(signal_id なしの注文はゲートで拒否)。執行層実装時の仕様
- ポッド別上限は IPS §3 の全体上限(合算 DD25%・レバ2.0x・集中度20%)より優先度が低い: 各ポッドが自分の上限内でも、合算が全体上限に触れれば中央リスク管理部が全体を止める
- ポッド内集中度が IPS の全体集中度(NAV の 20%)より大きく見えるのは分母が違うため(仮想資本 ¥200万の 40% = NAV の 8%)。ゲートは両方を判定する

## 4. 制約(研究知見・40-fund-managers.md から継承)

1. ペルソナ型エージェントは事前分布への固執を強める → **反証拠反転テスト(A-13)を FM に必須適用**
2. 成績評価は E9 補正済み指標のみ。ペルソナの物語性は評価に影響させない(Goodhart 対策)
3. 起動順: まず Ben と Jim(哲学が対極でテストに良い)。Stan/Peter は市場観・マクロ系(T-011)の安定後
