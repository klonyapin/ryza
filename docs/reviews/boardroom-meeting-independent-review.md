## 条件

- **C-1(重大)**: ガードは代表の最新1発言のみを見るため、多ターン分割と言い換えで素通りする。実測で「明日から本番でいこう」「デモはもう十分だ」「あと100万ほど」「go live with real capital」が全て未検出、一方 "tips" が `ips` 部分一致で誤検出。「LLM+決定論の二重担保」は現状成立せず実質一重。判定範囲を前回 IO 発言以降の代表発言に拡張し、口語・英語・`N万/N株/N倍` を追加。加えて **`mark_resolution` 側で「独立役員の発言なき決議」を検出する**決定論チェックを置く(決議は文言に依存しないため言い換えに強い)
- **C-2(重大)**: 発言を無サニタイズで連結するため、役員の出力に `代表: …` を含めるだけで後続役員・ルータ・議事録本文に代表の発言として混入する。防御はプロンプト1行のみ。話者ラベル行の無害化とフェンス化を要する(証憑の完全性=不変原則3)
- **C-3(重)**: stances 要約の入力が会議全文になり、記憶分離が「入力が構造的に role-pure」から「プロンプト依存」へ後退した。当該 role の発言のみに決定論フィルタすること。あわせて stances に出所種別を持たせ、盲検レビュー着任時に会議由来を除外できるようにする(代表の選好が stances 経由で盲検経路に透過する)
- **C-4(重)**: `minutes.run_id` は保存 run を指し routing を記録した会議 run と別。update_params は成功時のみ・選定元(router/guard/facilitator)を区別しない。§5 が謳う §6-5 の事後検証は現状成立しない
- **C-5(中)**: §2 は minutes を永続記憶と定義しており、§5 の「§6-2 の範囲外」は文書内で矛盾する。緩和は §6-2 本文の改訂として行うこと

## その他(非ブロック)
