## 設計リード裁定(2026-08-04)

**代替案(d)を採用し、週次ジョブの VM 移設は撤回する。** 是正ではなく作り直しを選ぶのは、(d)が重大-1・重大-2 を是正するのではなく**発生源ごと消す**からである。移設を前提に是正すると、重大-1 には全 deploy スクリプトへの git ゲート適用(あるいは週次からの監査だけを別 clone で走らせる二重構成)、重大-2 には timer のデッドマン検査という**新たな統制**が要り、統制を守るための統制が積み上がる。監査を A-18 側に置けば、監査専用 clone(重大-1)・`--always-report` のハートビート(重大-2 のデッドマン)・`#運営` への配送(中-5 の DB 非依存性を除く報告経路)は**既に存在する性質**として手に入る。

反対しておくべき点(審査への異論): 審査は移設判断の棄却根拠を「循環的」と評したが、循環していたのは**根拠の書き方**であって判断そのものではない。懸念4 の本文は表出先(週次ダイジェスト)を名指ししており、それを字義どおり満たす実装を選んだこと自体は不当ではない。とはいえ、統制の**実質**(独立した検出点)を満たす経路が他にあるなら、条文の字面より実質を優先すべきという審査の規範は正しい。以後、統制の配線を設計するときは「どの文書がどこに出せと書いたか」ではなく「その統制が何から独立していれば目的を果たすか」を先に書く。
