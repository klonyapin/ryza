# A-12 第1回フル実装監査 — 裁定書

**アーギュメント**: 別系統ベンダー AI(GLM-5)による7パスの実装監査は、統制の骨格(帳簿分離・証憑必須・fail-closed・発注経路の唯一性・追記オンリー)が設計どおり DB 制約とコード契約で強制されていることを独立に確認した一方、有効な所見 14 件(うち即時是正 4 件)を挙げた。最重要は「統制の発火期日を定義する `ops/reminders.yaml` が保護領域外にある」(A-12-15)であり、保護領域制度そのものを保護領域外のファイル変更で骨抜きにできる経路として直ちに塞ぐ。

## 1. 監査の方法と限界

- 監査人: GLM-5(Z.AI Anthropic 互換 API 直叩き)。プロンプト分離 — 設計文書と実装のみを渡し、実装者・設計リードの見解や過去の審査結論は渡していない。ランナーは `run_audit.py`(本ディレクトリに保存)
- 7 パス: pass1(ledger)/pass2(gate・risk・fm)/pass3(governance・audit)/pass4(セキュリティ境界)/pass5(テストの穴)+ 再監査 pass1b/pass3b
- **方法上の欠陥(裁定者の責任)**: 初回の pass1/pass3 に会計・ガバナンスのスキーマ DDL(0005/0006/0013/0019/0021/0029)と `secrets.py`・`ops/reminders.yaml` を渡し漏れた。その結果、初回の[重大]所見 6 件中 4 件は「監査資料の欠落」による誤検出だった。正しい資料で pass1b/pass3b を再実行し、該当領域は「所見なし」ないし別の小粒所見に置き換わった。**次回監査への教訓: 監査対象のファイルセットは領域の依存閉包(スキーマ・シード・共有ユーティリティ)まで含めて渡すこと**

## 4. 監査全体への評価

監査人は「実装全体の統制設計は極めて高い水準にある」と総括した(pass3 総括)。fail-closed の一貫適用・保護領域の積層(テストの独立参照)・申告の限界を docstring で開示する規律は、初回監査として肯定的に確認された。一方で本裁定は監査人の総括を鵜呑みにしない: 有効所見 14 件のうち F-1(保護領域制度の骨抜き経路)と F-5/F-6(取引・リスク経路の設計乖離)は、統制の「骨格は正しいが縁が甘い」ことを示しており、実弾移行前に全て解消する。
