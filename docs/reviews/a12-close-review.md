## §3 所見(重大/中/軽微)

### 【重大1】 F-1 行の「reminders.yaml の保護領域化」は事実誤認

**根拠**:
- 本裁定書 §3 F-1 は「config/governance.yaml の protected_areas に追加(area: governance_engine)」を是正内容として明記していた
- Issue #117 本文も「config/governance.yaml の protected_areas に ops/reminders.yaml を追加(area: governance_engine)」を要求している
- しかし PR #135 の本文は明示的に不採用理由を述べる: 「**全体の protected_areas 登録は不採用: 直近1週間で全コミットの 35%(166/473)が本ファイルに触れる実測から、登録の逆インセンティブを生むため。疑わしい変更だけを鳴らす semantic tamper check とする**」
- reviewed_sha fc62932 の `config/governance.yaml` を全走査した結果、`ops/reminders.yaml` は protected_areas に **登録されていない**(protected_areas 55 件中、reminders パスを含むエントリは0件)
- 実際の是正は A-18-9(監査コード側での意味的改ざん検出)であり、statically な「保護領域化」ではなく dynamically な監視である

**なぜ重大か**: 本裁定書は監査対象そのものであり(EQA と第2回 A-12 が本文を参照する)、対応表の記述が正確でないと、後続の追跡検査(第2回 A-12 の引き継ぎ②)が「F-1 の是正=protected_areas 登録」を探して発見できず、後退検査が空回りする。裁定書の記述は登録の**形式**を書いているのに実装は形式が違う——「監査ドキュメントの自己記述の正確性」は監査部門の根幹であり、譲れない。

**代替表記案**:
```
| F-1 | #117 | #135 | reminders.yaml 改変検出(A-18-9 意味的改ざん検査。裁定の protected_areas 登録は PR 本文の実測論拠により不採用、監査による代替統制) |
```
または脚注で「原案は protected_areas 登録だったが、直近実測で全コミット 35% が触れる高頻度ファイルであることから逆インセンティブが指摘され、A-18-9 の semantic tamper check に置換。設計変更の根拠は PR #135 本文」と明記。

### 【中1】 §4 の「実弾移行前に全て解消」約束と F-1 実装変質の説明欠落

**根拠**: 裁定書 §4 は「F-1(保護領域制度の骨抜き経路)... は実弾移行前に**全て解消**する」と書いた。しかし F-1 の実装は「保護領域制度そのもの」ではなく「監査による事後検出」で解決された。両者は統制上の性質が異なる(前者は事前禁止、後者は事後検知)。§6 はこの差分を説明せず「完了」とだけ書く。読者(第2回監査人・EQA)は §4 の骨抜き経路が解消されたかどうかを §6 だけからは判断できない。

**なぜ中か**: 【重大1】と同根の問題だが、こちらは「実弾移行前の未解決品目リスト」への影響。実弾移行判断時に「F-1 は保護領域化されず監査検出で置換された」ことを明示的に議事に上げる必要があり、§6 が完了扱いで葬ると議題落ちする。

**改善案**: §6 に一段落追加。「F-1 は §3 の原案(protected_areas 登録)から A-18-9 semantic tamper check に統制方式を変更した(PR #135 本文の実測論拠)。事前禁止から事後検知への性質転換は骨抜き経路の解消として同等性検証が必要であり、実弾移行前の統制監査(監査部門実効性評価)で改めて確認する — meta-audit-2026q4 の観点に含める」。
