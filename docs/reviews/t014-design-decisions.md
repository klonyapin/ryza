## 2. 独立役員審査(2026-08-03)の条件と反映

1. **累積約定 ≤ 注文数量**: `record_execution` が部分約定の合算+本約定 > 注文数量を例外で
   拒否(注文行 FOR UPDATE で並行 fill とも直列)
2. **TOCTOU 封鎖**: `gate_and_record` 冒頭で `pg_advisory_xact_lock(4014, hashtext(book_id))`
   により帳簿単位で判定〜記帳を直列化。並行2接続の直列化テストあり(`tests/gate/test_lock.py`)
3. **グロス計算の行単位化**: G-4/G-8 のファンド/資産クラスグロスは行単位 Σ|qty|×時価
   (ポッド間ネット廃止 — 両建ての過小評価を修正)
4. **単元例外はファンド集中度のみ**(§1 判断2)。E8 単一ポッド帳簿はファンド側判定で満たされる。
   **改訂提案の要否**: 現行マンデート(仮想資本 ¥200万×集中度 20〜50% = 絶対額 40〜100万円)では
   1単元 40万円超の銘柄をポッドが保有できない。設計上は意図どおり(高額単元はポッドの分散義務が
   優先)と考えるが、FM から高額単元銘柄の保有要望が出た場合は**マンデート改訂(投資委員会の
   みなし承認)で当該ポッドの集中度を引き上げる**のが正規経路であり、ゲート実装で緩めてはならない
5. **hedge_futures_only のヘッジ性判定**(§1 判断7)
6. **監査再現性**: `compliance.gate_log.state_ref` jsonb に判定時状態スナップショット
   (nav・cash・daily_turnover・trading_state・limits_state・使用価格・ポジション・trade_date)を
   記帳。保有銘柄の時価欠落は block(§1 判断10)
7. **分類フラグの安全側既定**: `is_single_name` の既定を `None`(分類不能)とし、依存規則
   (G-2 個別株禁止・G-9 個別銘柄ショート上限)は None を pass に落とさず block(reason=分類不能)

## 3. 残課題(後続タスクへの引き継ぎ)

- **T-015**: 銘柄マスタからの決定論分類(`universe_tags`・`is_single_name`・`instrument_flags`)の
  配線/時価(prices)の供給/NAV・現金の評価エンジン/`risk.limits_state` の算出
- **T-016**: 凍結中の例外取引(per_trade_user_approval)の承認済み経路/ブローカー接続
- **IPS 論点**(判断12): 単元例外と当日売買代金上限の整合(設計リード起票)
- `instrument_flags` は「空=フラグなし」と「未取得」を区別できない。銘柄マスタ側で取得状態を
  持たせるか、T-015 で分類の completeness を保証すること(条件7 の残り半分)
